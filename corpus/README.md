# Document Corpus

## Manifest

The corpus is described by a single manifest at `corpus/manifest.json`, keyed by
`production` and `malicious`. Each entry lists a file's format, page count,
notable features, and — for malicious files — its attack vector and the expected
(inert) behavior.

The `pages` field is normally an integer (the page count). For DOCX entries it
may instead be an **array of per-page dimensions or markers** (e.g. `[1, 2]` for a
two-page document) where a flat count isn't sufficient to describe the sample.

### Production samples (`production/`)

The production set holds **13 fully synthetic documents**, each byte produced by
[`scripts/generate-corpus.ts`](../scripts/generate-corpus.ts) — there are no
third-party or licensed samples in the corpus. Regenerate with `npm run
generate-corpus`.

| Category | Files present |
|---|---|
| PDFs | `simple.pdf`, `multipage.pdf` (3pp), `large-20page.pdf` (scroll/perf), `layers.pdf` (optional content groups), `annotations.pdf` (Square/FreeText/Link annotations) |
| DOCX | `simple.docx`, `tables.docx` (2×2 table) |
| Images | `minimal.jpg`, `minimal.png`, `minimal.gif`, `minimal.tiff`, `multipage.tiff` (3pp), `simple.svg` |

Supported image formats are the browser-native raster set (JPEG, PNG, GIF,
WebP), SVG (rendered inert via `<img src=blob:>`), TIFF (multi-page, worker
decode), and HEIC (main-thread decode). Several adapter capabilities are **not
yet backed by a license-free fixture** — see
[`MISSING-TEST-CASES.md`](./MISSING-TEST-CASES.md) for the outstanding coverage
(HEIC decode, large-image decode, blank PDF, and rich/imaged/multi-page DOCX).

### Malicious samples (`malicious/`)

> **Not committed to the repository.** `corpus/malicious/` is `.gitignore`d.
> These are functional (if inert) exploit payloads, and shipping them in a
> public repo invites antivirus/scanner false-positives and is poor practice.
> They are generated on demand from [`scripts/generate-corpus.ts`](../scripts/generate-corpus.ts):
>
> ```bash
> npm run generate-corpus
> ```
>
> `npm run test:security` regenerates them automatically (via a `pretest`
> hook), and CI does the same. The generator — not the payloads — is the
> committed source of truth.
>
> **The payloads are intentionally defused reproductions of the *structure* of
> each attack, not weapons:** remote references use the reserved, non-resolving
> `*.example.com` domain (RFC 2606); the "zip bomb" decompresses to a bounded
> ~10 MB (enough to trip the ratio/size caps, not exhaust memory); injected
> scripts only set a detectable flag; the path-traversal entry carries harmless
> content. They exist to prove the *defenses* fire, nothing more.

Each malicious sample has a documented attack vector (see `manifest.json` for
the authoritative list). The files produced by the generator:

| File | Attack vector | Expected behavior |
|---|---|---|
| `svg-script.svg` | `<script>` element inside SVG | Script must not execute; SVG renders inert via `<img src=blob:>` |
| `svg-foreignobject.svg` | SVG `foreignObject` embedding HTML | `foreignObject` content must not reach live DOM; rendered inert |
| `svg-remote-refs.svg` | Remote resource references | Zero network requests; remote refs dropped |
| `docx-javascript-hyperlink.docx` | `javascript:` URI in a hyperlink | Link stripped; no navigation or script execution |
| `docx-remote-images.docx` | Remote image reference | Remote image dropped; zero network requests |
| `zipped-zero-bomb.zip` | Compression bomb (high expansion ratio) | Rejected by the expansion-ratio cap before full decompression |
| `zip-path-traversal.zip` | `../` entry names in a zip | Rejected by path sanitization ('../' entries detected) |

**No PDF-malicious samples exist yet.** The PDF security invariants (JS actions
never execute, launch/GoToR actions never auto-trigger, XFA scripting never
runs) are enforced in the adapter but are **not yet backed by a corpus fixture** —
adding JS-action, launch-action, and XFA-form PDFs is outstanding work.

## Usage in tests

- `corpus/manifest.json` — the single source of truth; keyed by `production` and `malicious`
- Run `npm run generate-corpus` once (or `npm run test:security`, which does it
  automatically) to materialize `corpus/malicious/` locally
- Security tests load files under `corpus/malicious/` with network interception
- Visual regression uses `corpus/production/` with screenshot baselines

## Sources

Every file in this corpus is generated by `scripts/generate-corpus.ts` from
hand-authored byte templates — no third-party, licensed, or production documents
are committed. This keeps the corpus redistributable with zero licensing
obligations. The structure of the malicious payloads is informed by public
XSS/SVG attack corpora and the pdf.js test suite (MIT), but no bytes are copied
from them.
